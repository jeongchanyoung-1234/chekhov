# 「{{TITLE}}」 작업 규칙

AI 에이전트(와 사람 협업자)가 이 원고를 다룰 때 따르는 규칙이다. Claude Code라면 이 파일을 `CLAUDE.md`로, 다른 도구라면 `AGENTS.md` 등으로 두면 된다.

1. **모든 수정을 비판적으로 검토하고 적용한다.**
   - 작가의 제안이든, AI의 제안이든, 다른 사람이 넣은 내용이든 그대로 받아 적지 않는다.
   - 수정마다 따진다: 인물(페르소나)과 맞는가, 주제에 기여하는가, 그 장의 상황과 맞는가, 앞뒤 사실이 맞는가, 문장으로서 좋은가.
   - 적용하지 않았거나 다르게 적용한 것은 이유와 함께 보고한다.

2. **고치기 전에 `graph.json`의 invariants를 읽는다. 고친 뒤에는 그래프를 함께 고치고 검사한다.**
   - `storygraph check graph.json 원고.docx`
   - 장면을 바꾸면 해당 Event의 `evidence`(원고 문장)와 간선도 고친다. 검사기가 잡지 못하는 어긋남(규칙 문장 안의 설명 등)도 함께 고친다.
   - 장면을 빼면 `storygraph impact`로 짝을 잃은 복선·운을 확인하고, 남은 쪽이 여전히 서는지 다시 읽는다.

3. **원본은 고치지 않는다.**
   - 작업 중인 판은 번호를 붙여 따로 저장한다(`_v0.2_작업1` 등). 마감하면 새 완료본과 원본만 남긴다.
   - 축약판(공모용 등)은 별도 파일로 두고, 일부러 뺀 노드는 제외 목록 파일에 적는다.

4. **작업 전에 `FEEDBACK_LOG.md`를 읽고, 회차가 끝날 때마다 갱신한다.**
   - 새 원칙은 1부에, 작업 기록은 2부에, AI의 실수는 3부에 적는다.
   - 작가가 한 말과 AI의 해석을 [작가]/[해석]으로 구분한다.
   - 2부의 "다음에 정할 것"을 먼저 확인한다.

5. **판단은 작가가 한다.** 설계(인물의 의미, 결말, 상징의 해석)를 바꾸는 제안은 적용하기 전에 묻는다. 설계를 증명하려고 새 문장을 끼워 넣지 않는다.
